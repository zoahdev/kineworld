# KW-LEWM-0003 — 用数据集定义的真实任务评估 LeWM（消除随机任务混淆项）

- 日期：2026-09-03
- 类型：**协议修正后的复现**（无训练，仅推理）
- 前置：`KW-LEWM-0002` 判定 `ACTION_SCALER_NECESSARY_NOT_SUFFICIENT`，遗留混淆项"任务随机采样"
- 脚本：`verification/scripts/kw_lewm_0003_dataset_tasks.py`
- 结果：`results/kw_lewm_0003_dataset_tasks.json`

---

## 1. 为什么要做这个实验

KW-LEWM-0002 修复了 action 逆变换后，控制从"必然飞出场地"改善到"6/8 在场内"，但：

- 仍有 2/8 越界；
- block 位移**中位数 0.0**；
- **success 0/8**。

把 0/8 读作"LeWM 能力差"是**无效推论**，因为任务本身是随机采样的：起点到目标的 4 维距离最高 360.9，且成功判定要求 block 位姿精确对齐（`pos_diff < 20` 且 `angle_diff < π/9`）。随机配对的 start/goal **不保证可达**。

官方协议用的是**同一 episode 内相隔 25 步的真实状态对**——由构造保证可达。本实验改用这类任务。

## 2. 在不动 13.1 GB 数据集的前提下如何拿到官方任务

官方 `World.evaluate(dataset=...)` 只要求 dataset 提供两样东西：

1. `column_names`
2. `load_chunk(episodes_idx, start_steps, end_steps)` → list of dict

`_extract_init_goal` 只读 `arr[0]`（init）和 `arr[-1]`（goal）。因此构造一个 **shim dataset** 即可：

| 数据 | 来源 | 说明 |
|---|---|---|
| start/goal state | 公开 parquet 分片 | 同 episode、相隔 25 步，可达 |
| **pixels** | **本地渲染** | 数值传输从未下载图像列，用 `AddPixelsWrapper._get_pixels()` 按 state 渲染 224×224 |
| 传入环境 | `evaluate(callables=...)` | 调 `_set_state` / `_set_goal_state` |

### 2.1 本地渲染的确定性验证

| 检查 | 结果 |
|---|---|
| 不同 state 渲染出的图像平均差 | 4.045（>0，渲染随 state 变化） |
| 同一 state 重复渲染的差异 | **0.0**（确定性） |
| 图像规格 | (224, 224, 3) uint8 |

### 2.2 保留 KW-LEWM-0002 的成果

`process={"action": StandardScaler}`，统计量来自 parquet 的 80,384 行（mean ≈ -0.0359/0.0071，scale ≈ 0.1875/0.1970）。

## 4. Kill Criteria

- **K1（任务来源有影响）**：block 交互率（位移 > 1.0 的任务比例）**高于** KW-LEWM-0002 随机任务基线的 3/8 = 0.375。若不满足 → 随机任务不是混淆项，0/8 另有原因，需重新归因。
- **K2（控制合法）**：agent 全部留在 `[0, 512]²` 内。

### 5.4 统计边界（必须一起读）

**n = 8 太小，点估计本身没有信息量**：

| | 点估计 | Wilson 95% CI | 宽度 |
|---|---:|---|---:|
| 0003 success | 3/8 = 0.375 | **[0.137, 0.694]** | 0.557 |
| 0002 success | 0/8 = 0.000 | [0.000, 0.324] | 0.324 |

0.375 的真实含义是"在 14%–69% 之间的某个位置"。本实验**只能**支撑定性结论——**可达任务下 LeWM 产生有效控制，随机任务下不产生**——不能支撑任何精确成功率声明。

因此下一步 KW-LEWM-0004 把任务数扩到 **50**（贴近官方 50 evaluations），Wilson 宽度可收窄至约 0.26。

### 5.5 方法论发现（本实验最有价值的产出）

**任务可达性是世界模型评测的关键混淆变量**，其影响量级超过被测模型的差异：同一个 checkpoint、同一个 planner、同一个 scaler，仅因任务从"随机采样"换成"数据集中相隔 25 步的真实状态对"，block 位移中位数就从 **0.0 变成 27.91**，成功率从 **0/8 变成 3/8**。

这意味着：任何在随机配对任务上报告的世界模型"成功率"，都可能主要反映**任务构造**而非模型能力。这直接落在 KineWorld 的评测/基准方法论主线上，值得作为独立结论保留。

## 6. 边界（必须随任何引用一起保留）

本实验**仍然不是**官方 13.1 GB 数据集 benchmark。残留近似：

1. **scaler 近似**：来自 partial shard 的 80,384 行，非官方全量训练集；
2. **像素本地渲染**：与官方数据集里真实记录的像素不完全一致（渲染器版本、抗锯齿等）；
3. **CEM 缩减**：10×100×10 而非官方 30×300×30；
4. **任务数**：8 个，非官方 50 个；
5. **仅 shard 0**：未覆盖全部分片。

因此：

**允许**：在披露的 lite 协议下，LeWM 官方权重在数据集定义的真实任务上完成了 N/8，agent 行为合法。
**禁止**：官方 benchmark 已复现；与 JEPA-WM 或任何竞品比较（本实验无同协议对照组）；第三方验证（仍为 E1）。
