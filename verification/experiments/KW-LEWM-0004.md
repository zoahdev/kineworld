# KW-LEWM-0004 — 数据集定义任务 50 任务扩展（收紧成功率置信区间）

- 日期：2026-09-03
- 类型：**协议修正后的复现（n 扩展，无训练，仅推理）**
- 前置：`KW-LEWM-0003` 判定 `DATASET_TASKS_UNLOCK_VALID_CONTROL`，但 n=8 的 Wilson 宽度 0.557，只能支撑定性结论
- 脚本：`verification/scripts/kw_lewm_0003_dataset_tasks.py --pairs 50`
- 结果：`results/kw_lewm_0004_dataset_tasks_p50.json`

---

## 1. 为什么要做

`KW-LEWM-0003` 在 8 个数据集定义任务上得到 success 3/8 = 0.375，Wilson 95% CI = [0.137, 0.694]（宽度 0.557）。这个 CI 太宽，点估计几乎没有信息量——0.375 的真实含义是"在 14%–69% 之间的某个位置"。

本实验把任务数扩到 **50**（贴近官方 50 evaluations），预期把宽度收窄到约 0.26，使"可达任务下 LeWM 产生有效控制"从定性结论升级为可量化的区间估计。

其余协议**完全不变**（同一 scaler、同一 CEM 10×100×10、同一 shim dataset 结构、本地渲染像素），唯一增加的是任务数量。这保证了 0003 → 0004 是**纯 n 扩展**，不引入新变量。

## 2. 配置

| 项 | 值 |
|---|---|

## 3. Kill Criteria

本实验是 0003 的 n 扩展，**无新 kill gate**。预注册通过标准：

- **K2（控制合法）**：沿用 0003 —— agent 全部留在 `[0,512]²`（out_of_play_rate = 0）。
- **K1（任务来源仍成立）**：block 交互率 > 0.375（0002 随机任务基线）。
- **统计目标**：Wilson 95% 宽度 < 0.30。

任一不达成 → 0003 结论不稳，需重新归因。

## 4. 结果（2026-09-03，50 个数据集定义任务）

- 状态：**完成**
- 判定：**`DATASET_TASKS_UNLOCK_VALID_CONTROL`（已确认，本轮为区间收紧）**

| 判据 | 结果 |
|---|---|
| **K2（控制合法）** | ✅ 通过：0/50 越界 |
| **K1（任务来源仍成立）** | ✅ 通过：block 交互率 0.88 > 0.375 |

### 4.3 置信区间收紧

| | 点估计 | Wilson 95% CI | 宽度 |
|---|---:|---|---:|
| 0002（随机任务） | 0.000 | [0.000, 0.324] | 0.324 |
| 0003（数据集 8） | 0.375 | [0.137, 0.694] | 0.557 |
| **0004（数据集 50）** | **0.360** | **[0.241, 0.499]** | **0.257** |

**关键**：0004 点估计 0.36 与 0003 的 0.375 **几乎重合**，且 CI 大幅收窄。这意味着 0003 的 8 任务估计**不是小样本噪声**——可达任务下 LeWM 的真实成功率落在约 24%–50%。区间**下界 0.241 远高于 0**，与随机任务的 0 形成清晰分离，足以否定"LeWM 在可达任务上完全无效"。

### 4.4 success 不随任务距离变化（再次确认混淆项结论）

Spearman 相关（n=50，手动实现，无 scipy 依赖）：

- success ~ start_goal_distance：**ρ = 0.055**（≈0，无关系）
- success ~ block_displacement：ρ = -0.228（弱；更多 block 位移与更低 success 弱相关，可能反映"需大幅推 block 的任务更难"，但效应弱，不展开）

ρ ≈ 0 确认：在数据集定义的可达任务集内，成功与否**不由任务几何距离决定**，与 0003 §5.3 的观察一致——成功取决于 4 维 agent+block 位姿联合对齐，而非简单距离。这进一步坐实 0003 的方法论发现：**随机配对之所以 0/8，是因为任务不可达，不是因为距离远**。

### 4.5 数据完整性备注（必须随引用一起保留）

结果 JSON `results/kw_lewm_0004_dataset_tasks_p50.json` 由 0003 脚本加 `--pairs 50` 直接生成，因此：

- 内部 `experiment_id` 字段仍为 `"KW-LEWM-0003-DATASET-TASKS"`（schema 沿用，非笔误）；
- `baseline_for_comparison` 仅指向 0002（随机任务），未含 0003（8 数据集任务）。

正确理解的三级阶梯是 **0002（随机）→ 0003（数据集 8）→ 0004（数据集 50）**。本实验结果数字已逐字段与文件自带 `summary` 交叉核对一致（`n_success=18`、`n_out_of_play=0` 均吻合），仅元数据标签为沿用值。

## 5. 统计边界（必须一起读）

- n=50 把区间宽度从 0.557 收到 0.257，**仍不足以支撑精确成功率**（真实值在 24%–50% 之间）。
- 区间下界 0.241 > 0，足以否定"LeWM 在可达任务上完全无效"，但**不足以**与官方全量 benchmark（13.1 GB、官方 CEM、官方像素）做定量比较。
- 点估计 0.36 是在**缩减 CEM（10×100×10）**下得到的；官方 30×300×30 可能更高，本实验不声称任何官方数字。

## 6. 边界（必须随任何引用一起保留）

同 0003，本实验**仍然不是**官方 13.1 GB 数据集 benchmark。残留近似：

1. **scaler 近似**：来自 partial shard 的 80,384 行，非官方全量训练集；
2. **像素本地渲染**：与官方数据集里真实记录的像素不完全一致（渲染器版本、抗锯齿等）；
3. **CEM 缩减**：10×100×10 而非官方 30×300×30；
4. **仅 shard 0**：未覆盖全部分片；
5. **单分片 / 单 goal_offset=25**：50 个任务来自同一分片、同一相隔步数。

**允许**：在披露的 lite 协议下，LeWM 官方权重在数据集定义可达任务上的成功率约 0.36（95% CI [0.24, 0.50]），agent 行为合法（0/50 越界）。
**禁止**：官方 benchmark 已复现；与 JEPA-WM 或任何竞品比较（无同协议对照组）；第三方验证（仍为 E1）；用 0.36 作为官方数字。

## 7. 与 0003 的方法论主线衔接

KW-LEWM-0002 → 0003 → 0004 构成一条干净的因果链，每一步只动一个变量：

| 实验 | 动的变量 | 结论 |
|---|---|---|
| 0002 | action 逆变换（identity → scaler） | 缺失逆变换是 0001L 失效机制之一，但非充分 → `ACTION_SCALER_NECESSARY_NOT_SUFFICIENT` |
| 0003 | 任务来源（随机 → 数据集可达） | 任务可达性解锁有效控制 → `DATASET_TASKS_UNLOCK_VALID_CONTROL` + 方法论发现 |
| 0004 | 仅扩 n（8 → 50） | 点估计稳定（0.375→0.36）、CI 收窄（0.557→0.257），0003 非小样本假象 |

到此，LeWM 复现线在 lite 协议下已自洽闭环：**权重来源核验（0001L）+ 控制机制（0002）+ 任务可达性混淆项（0003）+ 区间收紧（0004）**。下一步若要晋级到"官方 benchmark 同台对比"，必须先把 JEPA-WM 接入同一 `stable-worldmodel` 平台、同任务、同 CEM 预算，否则任何"vs JEPA-WM"的声明都违反本项目证据纪律。
